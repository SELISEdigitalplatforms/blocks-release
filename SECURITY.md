# Security Policy

## Supported Versions

Security fixes are applied to the latest released version on the default branch. Older snapshots are not maintained separately, so please reproduce and report issues against the most recent code before filing a report.

| Version | Supported |
| --- | --- |
| Latest release (default branch) | Yes |
| Older commits or tags | No |

## Reporting a Vulnerability

If you believe you have found a security vulnerability, please report it privately. We take all reports seriously and will do our best to address confirmed issues promptly.

**Do not create a public GitHub issue for a security vulnerability.**

Instead:

1. Email [blocks@selisegroup.com](mailto:blocks@selisegroup.com) with the details.
2. Include a clear description, the affected component or endpoint, reproduction steps, and the impact you observed.
3. Include any relevant environment details (versions, configuration) that help us reproduce it.
4. Give us reasonable time to investigate and respond before any public disclosure.

You may also use GitHub's private vulnerability reporting for this repository if it is enabled.

## Response Expectations

- **Acknowledgement**: we aim to confirm receipt of your report within a few business days.
- **Assessment**: we will work with you to validate the issue and determine its severity and scope.
- **Resolution**: once confirmed, we will prepare and ship a fix, and keep you informed of progress and timelines.
- **Credit**: if you wish, we will credit you when the issue is resolved.

## Responsible Disclosure

We appreciate the efforts of security researchers and the community in keeping this project and its users safe. If you responsibly disclose a security issue, we commit to:

- Acknowledge and respond to your report.
- Work with you to understand and validate the issue.
- Provide details on when and how the issue will be addressed.
- Give credit to the reporter, if agreed upon, upon resolution.

## Scope

This policy applies to the code in this repository. It does not grant permission to attack, disrupt, or exploit any hosted service, deployment, or infrastructure. Testing must be limited to code you run yourself in your own environment.

## Updates

We may update this policy from time to time. Check the file's Git history for the most recent changes.
